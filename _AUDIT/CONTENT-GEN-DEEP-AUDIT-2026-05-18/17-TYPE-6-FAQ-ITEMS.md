## 1. Description simple (Will-readable)

Les FAQ items sont des questions/réponses publiées sur `/fr/faq` et `/fr/faq/[slug]`. Deux mécanismes alimentent cette base : (1) le generator `faq-standalone` pour créer une Q/R seule, (2) le post-process `qa-derived` qui extrait automatiquement les Q/R intégrées dans un article publié et crée une page dédiée par question. Le tout passe par la table Prisma `FAQ`, exposée via le reader `listFaqs()` qui fusionne aussi le FAQ_GLOBAL hardcoded. Chaque page Q/R porte un JSON-LD QAPage + Speakable pour citation directe par Perplexity / ChatGPT / Bing.

## 4. Quality gates (ordre)

Pour FAQ, les gates sont segmentés en 3 paths :

**Path A — generator standalone** (squelette V1) :

1. `Generator` type contract (`generators/types.ts`).
2. Délégation à `landingVilleGenerator` qui hérite des gates landing-ville : KB hard gate, LLM call, quality loop, soft-404 gate 350 mots (cf `_AUDIT/.../14-TYPE-3-LANDING-VILLE.md` si existe).
3. Aucune gate spécifique FAQ (wordcount par réponse, anti-duplicate questions, etc.) — **gap V1**.

**Path B — post-process auto** (`content-qa-extract-worker.ts`) :

1. **Kill switch** hardgate (L66-72) — si `kill_switch.active=true`, throw « kill_switch_active » → requeue indéfini.
2. **Empty input guard** : `faqs.length === 0` → `logStep "No FAQs to extract — skipping"` + early return (L74-77).
3. **Slug guard** : `slug.length < 10` → skip + counter (L89-92) — protection slug dégénéré.
4. **Upsert idempotent** : `prisma.fAQ.upsert({ where: { slug }, create, update })` (L94) — re-publication article = refresh Q/R, jamais doublon.
5. **Truncation** : `question.slice(0, 500)`, `answer` non tronqué (L99-102, L119-120) — risque réponse 50 000 chars sans cap.
6. **Indexation par défaut tier_2_noindex_follow** (L114) — anti-doorway HCU strict V1. Will promote tier_1 manuellement après enrichment V1.5.
7. **Revalidation best-effort** : `revalidatePath("/fr/faq")` (L139), no-op silencieux en worker bg (L140-142).
8. **BullMQ retention bornage** : `removeOnComplete: 1000`, `removeOnFail: 5000` (L168-169 P2-23 audit indexation).
9. **Aucune gate** : PII scan / banned words / quality / dedup cosine — non appliquées à la Q/R extraite (ils sont appliqués à l'article parent en amont, mais pas re-vérifiés ici).

**Path C — reader public** (`readers.ts:listFaqs`) : 10. Filtre DB : `status="published"` + `indexationTier ∈ {tier_1_indexable, tier_2_noindex_follow}` (L176-178) — tier_3 exclu. 11. Slug obligatoire : `r.slug === null` → ignoré (L184-185). 12. Cap 5000 rows (L181). 13. Dédup `mergeFaqs(a, b)` priorité source A (L210-214).

## 7. Erreurs / edge cases

- **Generators squelettes (`faq-standalone.ts:14-18` et `qa-derived.ts:18-21`)** : délégation aveugle à `landingVilleGenerator`. Le `landingVilleGenerator` sait-il gérer un input sans ville ancre ? **UNKNOWN — requires fact-check** : lire `landing-ville.ts` pour confirmer fallback `villeSlug=undefined`. Si non, ces generators crashent en runtime sur un input FAQ pur.
- **Path B contourne KB feeder** : `content-qa-extract-worker.ts` insère direct dans `prisma.fAQ` (L94) sans passer par `publishToKB`. Conséquence : les Q/R auto **n'apparaissent jamais dans `KnowledgeEntry`**, donc invisibles si Will active `KB_BACKEND_UNIFIED_FAQ=1` (le reader bascule sur KB-only et les Q/R DB-table sont quand même merged via `loadAutoGeneratedFaqs` L116+L162, donc OK mais double source non gérée par audit log KB).
- **Question + Answer non sanitisés** : `slugifyQuestion` strip caractères mais `answerFr/En` sont stockés tels quels (L101). Si l'article parent contient `<script>` ou onclick injection dans le faqJson, c'est propagé à la page FAQ. Aucun appel `sanitize-html` / `tiptap-sanitize` ici.
- **Placeholder EN = FR** (`content-qa-extract-worker.ts:99-102`) : `questionEn: question.slice(0, 500)` mais `question` est en FR. Si EN locale réactivé, toutes les FAQ DB auto-générées seront en français servies depuis `/en/faq/[slug]`. → P0 si EN ré-ouvert.
- **`revalidatePath("/fr/faq")` no-op silencieux en worker bg** (L139-142) : nouvelle Q/R n'apparaît qu'après refresh ISR naturel (probable revalidate=3600 ou pas de revalidate explicite sur hub — **UNKNOWN — requires fact-check** : page hub `/faq/page.tsx` n'expose pas `export const revalidate`). Délai jusqu'à 1h.
- **Cap 5000 rows reader** (`readers.ts:181`) : si Will scale à 10 000 Q/R DB-generated, 5000 seront silencieusement coupées. Pas d'alerte / pagination.
- **Sitemap V1 limitation** (`sitemap.ts:579-580`) : `buildFaqSitemap` n'expose QUE FAQ_GLOBAL legacy. Les centaines de Q/R post-process auto sont absentes du sitemap → invisibles Googlebot (jusqu'à découverte par lien interne). → **P0** : faire builder lire `prisma.fAQ where indexationTier='tier_1_indexable' and status='published'`.
- **`tier_2_noindex_follow` par défaut** (`worker:114`) : Will doit promote manuellement chaque Q/R à tier_1 pour qu'elle soit indexable. Friction massive à 100+ Q/R. Pas de workflow batch admin documenté.
- **`BUILD_DATE` partagé** (`[slug]/page.tsx:75-78`) : toutes les FAQ ont `datePublished == dateModified == BUILD_DATE` (timestamp build). Au prochain deploy, toutes les Q/R « changent ». Google peut détecter signal artificiel.
- **Hub `/{locale}/faq` non-FR exposé** : la page (L47) ne fait pas de `notFound()` si locale ≠ FR (contrairement à `/connaissances`). Si EN désactivé via 301 proxy → utilisateur redirigé. Si EN ré-ouvert, page sert items dont `answerEn === answerFr` (placeholder).
- **Idempotency upsert + dépublication article parent** : si l'article parent est dépublié, les FAQ rows persistées **restent live** (pas de cascade). → ghost FAQ orphelines pointant vers Article supprimé via `parentArticleId`.
- **`category="general"` hardcoded** (`worker:98`) : aucune segmentation thématique automatique. Hub `FaqHeroSchema` affiche « 3 thématiques » (interventions/audit/souveraineté) mais aucune logique de routing automatique.
- **EN feed.xml runtime nodejs** (`feed.xml/route.ts:11`) : OK car Prisma. Mais `cas-concrets/feed.xml` est `runtime=edge` (incohérence inter-fichiers du même type).
