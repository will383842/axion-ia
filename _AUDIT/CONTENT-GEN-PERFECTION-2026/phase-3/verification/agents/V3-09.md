## Check 4 — JSON-LD Person Deduplication Risk (18 / 20 pts)

### Requirement
- AuthorByline.tsx emits inline Person JSON-LD
- guides/[slug]/page.tsx calls buildArticleJsonLd (fallback when no structured steps)
- Risk: TWO Person JSON-LDs emitted on same page

### Findings

**buildArticleJsonLd Structure** (src/lib/seo.ts, lines 635-639):
- Includes nested Person JSON-LD with name and URL

**AuthorByline Structure** (src/components/knowledge/public/AuthorByline.tsx):
- Emits separate Person JSON-LD via JsonLd component

**guides/[slug]/page.tsx Render**:
When guide.hasStructuredSteps === false:
1. Article JSON-LD with nested Person author (from buildArticleJsonLd)
2. AuthorByline component with separate Person JSON-LD

Result: TWO Person JSON-LDs on same page with same name "Manon"

### Risk Assessment
MEDIUM RISK (non-blocking):
- Google Search Console deduplicates by name + type in most cases
- Schema.org spec allows multiple Person declarations
- No functional harm, but adds ~50 bytes redundant JSON-LD per page
- Best practice: Dedup by passing authorName="Manon" to buildArticleJsonLd and omitting AuthorByline when !hasStructuredSteps

### Mitigation Options (not implemented, acceptable):
1. Remove AuthorByline from guides when !hasStructuredSteps
2. Pass authorName="Manon" to buildArticleJsonLd and omit AuthorByline
3. Accept current redundancy (Google handles gracefully)

### Score
18 / 20 — Redundant Person JSON-LD identified. Not breaking, but non-critical redundancy in render logic. Deduct 2 points.
