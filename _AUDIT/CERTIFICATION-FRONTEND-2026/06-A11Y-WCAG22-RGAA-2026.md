# 06 — A11Y WCAG 2.2 AA + RGAA France 2026

> Audit accessibilité conforme WCAG 2.2 AA et RGAA 4.1 (France).

## Audit en 6 chapitres × 10 critères = 60 points

### 1. Structure & sémantique

1.1 1 `<h1>` unique par page
1.2 Hiérarchie h1→h6 stricte (pas de skip)
1.3 Landmarks ARIA : `<header>`, `<nav>`, `<main>`, `<footer>`, `<aside>`
1.4 `<main>` unique par page
1.5 Skip-to-content fonctionnel (déjà ✅)
1.6 `lang` attribute par locale (déjà ✅)
1.7 Lists `<ul>/<ol>` quand sémantiquement liste
1.8 Tableaux `<table>` avec `<th scope>` + `<caption>` si data
1.9 `<button>` vs `<a>` correct (action vs navigation)
1.10 `<figure>` + `<figcaption>` quand pertinent

### 2. Clavier & focus

2.1 Tab navigation 100 % parcours possible
2.2 Tab order logique (DOM order)
2.3 Focus visible partout (`:focus-visible` ring)
2.4 Focus trap dans modals/menus déroulants
2.5 Esc ferme modals/menus
2.6 Enter/Space activent buttons
2.7 Arrow keys dans menus/tabs (ARIA design pattern)
2.8 Pas de `tabindex` > 0 (mauvaise pratique)
2.9 `tabindex="-1"` justifié (programmatic focus)
2.10 Skip-to-content sauf au début

### 3. ARIA & screen reader

3.1 Composants ARIA Authoring Practices respectés (Radix UI ✅)
3.2 `aria-label` sur icon-only buttons
3.3 `aria-labelledby` quand label visible
3.4 `aria-describedby` pour aides + erreurs forms
3.5 `aria-expanded` sur disclosure (menus, accordions)
3.6 `aria-current="page"` sur lien actif nav
3.7 `role="alert"` ou `aria-live="polite/assertive"` pour notifications
3.8 `aria-hidden="true"` sur décoratif (icons SVG dupliquées texte)
3.9 Pas d'ARIA contradictoire (vérifier Axe-core)
3.10 Test screen reader VoiceOver/NVDA sur 5 parcours critiques (manuel)

### 4. Contraste & visuel

4.1 Texte normal ≥ 4.5:1 (WCAG AA)
4.2 Texte large (≥ 18px ou 14px bold) ≥ 3:1
4.3 UI components ≥ 3:1 (icons interactifs, borders)
4.4 Focus indicator contraste ≥ 3:1
4.5 Pas d'info par couleur seule (forme + couleur)
4.6 Lighthouse contrast 100/100
4.7 Axe-core 0 violation contraste
4.8 Dark mode contraste OK (si activé)
4.9 Color blindness simulator OK (Chrome DevTools)
4.10 Texte sur image : overlay ou color stop garantissent contraste

### 5. Forms & interactions

5.1 Tous `<input>` ont `<label>` associé
5.2 Required marqué visuellement + `required` attr + `aria-required="true"`
5.3 Erreurs annoncées via `aria-describedby` + `role="alert"`
5.4 Erreurs reliées au champ
5.5 Autocomplete attributes corrects (`autocomplete="email"`, etc.)
5.6 `inputmode` adapté (numeric, email, tel)
5.7 Placeholder ne remplace jamais label
5.8 Submit button bien identifié (texte explicite)
5.9 Confirmation ou erreur post-submit annoncée
5.10 Forms validables clavier seul

### 6. Mobile & motion

6.1 Tap target ≥ 44×44 px (WCAG 2.2 AA = 24×24 minimum, viser 44)
6.2 Pinch-zoom autorisé (`viewport` `user-scalable=yes` ou pas de `maximum-scale`)
6.3 Pas de hover-only interactions (mobile no hover)
6.4 Gestes alternatifs (swipe → button également)
6.5 Orientation portrait + paysage OK
6.6 `prefers-reduced-motion` désactive animations non essentielles
6.7 Pas d'auto-play vidéo/carousel sans pause control
6.8 Pas de flash > 3 fois/sec (épilepsie)
6.9 Time limits (form expiration) ajustables ou désactivables (WCAG)
6.10 RGAA déclaration accessibilité publiée (page dédiée, statut FR)

## Méthode

- Phase A : Lighthouse a11y + Axe-core sur 15 pages × FR+EN
- Phase A bis : Manual screen reader test 5 parcours

- Phase C : Plan

3. Avant tout commit
