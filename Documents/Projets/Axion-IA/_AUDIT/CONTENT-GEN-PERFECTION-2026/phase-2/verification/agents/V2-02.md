### content-quality-improver-worker.ts (commit c1bfa6e) ❌
```typescript
workerInstance = new Worker<QualityImproveJobPayload>(QUEUE_NAME, processJob, {
  connection: { url: redisUrl },
  concurrency: 2,
  limiter: { max: 5, duration: 60_000 },  // rate limit, PAS lockDuration
  removeOnComplete: { count: 1000 },
  removeOnFail: { count: 5000 },
});
```
Le commit c1bfa6e a ajouté un **`limiter`** (rate limit BullMQ) au lieu d'un **`lockDuration`**. Ce sont deux options distinctes :
- `limiter`: limite le débit de traitement
- `lockDuration`: empêche la reprise du job par un autre worker en cas de durée > 30s

**Le risque de double-exécution du quality-improver reste présent.** Un article long soumis au quality-improver (Claude Sonnet review > 30s) peut être repris par un 2e worker.
