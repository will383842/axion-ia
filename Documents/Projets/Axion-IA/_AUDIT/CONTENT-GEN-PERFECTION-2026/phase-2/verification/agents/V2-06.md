## Analyse détaillée

### Migration SQL (présente, nullable)
`prisma/migrations/20260521150200_add_article_campaign_id/migration.sql` :
```sql
ALTER TABLE "articles" ADD COLUMN IF NOT EXISTS "campaign_id" VARCHAR(25);
CREATE INDEX CONCURRENTLY IF NOT EXISTS "articles_campaign_id_idx" ON "articles"("campaign_id");
```
Commentaire : *"ajout campaign_id nullable (rétro-compat articles existants)"*

**Écart vs spec P0** : la spec demandait NOT NULL, le commit a livré NULLABLE délibérément (comme indiqué dans le commit message "Article.campaignId nullable (migration + index)").

### Schema Prisma (non synchronisé)
`prisma/schema.prisma` modèle `Article` (lignes 874-974) : **aucune occurrence** de `campaignId` ou `campaign_id`. Le seul `campaignId String?` du fichier (ligne 2936) appartient au modèle `ContentGenJob`.

Le Prisma client ne connaît pas `Article.campaignId` → toute tentative d'accès via l'API fluent échoue.

### content-publish-worker.ts (worker non mis à jour)
`tx.article.create({ data: { ... } })` (lignes 289-321) : `campaignId` absent du `data:`. Même si le schema était synchronisé, le worker ne peuplerait pas le champ.

### Propagation partielle dans keyword-selector.ts
`campaignId` est passé à `selectKeyword()` pour le log `keyword_select_exhausted` seulement. Cela ne concerne pas la création d'articles.

## Conséquence en production
Les articles créés n'ont pas de `campaignId` en DB. La traçabilité campagne → article n'existe qu'indirectement via `article.generatedByJobId → ContentGenJob.campaignId`. Un bug de routing ne serait pas détecté par contrainte DB.

## Écart scope vs verdict P2 initial
Le P0-6 demandait `NOT NULL`. La décision de livrer NULLABLE était peut-être pragmatique (backfill articles historiques difficile), mais même la version NULLABLE n'est pas câblée côté applicatif.

## Effort correctif résiduel : ~2h
1. Ajouter dans `model Article` dans schema.prisma :
   ```prisma
   campaignId String?  @map("campaign_id") @db.VarChar(25)
   ```
2. `pnpm prisma migrate dev --name sync_article_campaign_id` (delta minimal si colonne SQL déjà là)
3. Dans `content-publish-worker.ts` `tx.article.create` data :
   ```typescript
   ...(cgJob.campaignId ? { campaignId: cgJob.campaignId } : {}),
   ```
