## Implémentation vérifiée

### Séquence atomique (lignes 153-187)
```typescript
const redisKey = `axion:pub:${format(new Date(), 'yyyyMMdd')}`;
const countAfterIncr = await redis.incr(redisKey);  // L162 — atomique
if (countAfterIncr === 1) {
  // Premier job du jour — pose l'EXPIRE à minuit UTC
  const midnight = new Date(); midnight.setUTCHours(24, 0, 0, 0);
  const ttl = Math.floor((midnight.getTime() - Date.now()) / 1000);
  await redis.expire(redisKey, ttl);  // TTL dynamique
}
if (countAfterIncr > maxPublishPerDay) {
  await redis.decr(redisKey);  // Annulation compensatoire
  await job.moveToDelayed(nextWindowTs);  // Re-enqueue 8h CET
  return;  // Pas de publication
}
// ... suite publish
```

### Points forts
- INCR exécuté avant toute logique DB → atomicité garantie
- DECR compensatoire en cas de dépassement → compteur fiable
- `moveToDelayed` → pas de job perdu, re-essai automatique à la prochaine fenêtre
- jobId déterministe pour idempotence

### Points faibles mineurs
- Test throttle : couvre INCR=31>cap, DECR vérifié, mais pas de `Promise.all` avec 3 workers concurrents simulés
- Si Redis down : job fail → BullMQ retry (3×) → eventually dead → no publish, mais pas de bypass loggué
