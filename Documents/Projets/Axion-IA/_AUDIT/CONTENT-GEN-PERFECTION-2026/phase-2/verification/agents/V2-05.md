## Analyse détaillée

### Migration SQL ✅ (seule partie correcte)
`prisma/migrations/20260521150100_add_keyword_lock_fields/migration.sql` :
```sql
ALTER TABLE "keywords" ADD COLUMN IF NOT EXISTS "locked_until" TIMESTAMPTZ;
ALTER TABLE "keywords" ADD COLUMN IF NOT EXISTS "locked_by" VARCHAR(120);
-- Pattern attendu : keywords avec locked_until IS NULL OR locked_until < now() sont eligibles
-- keywords avec locked_until > now() et locked_by = <jobId> = en cours de traitement
```
Colonnes ajoutées en DB. L'infrastructure SQL existe.

### Schema Prisma ❌ (non synchronisé)
`prisma/schema.prisma` modèle `Keyword` (lignes 3237-3256) : aucun champ `lockedUntil`/`lockedBy`. Le Prisma client ne connaît pas ces champs → impossible d'y accéder via l'API fluent.

### keyword-selector.ts ❌ (applicatif non câblé)
L'UPDATE de sélection fait uniquement :
```sql
SET usage_count = usage_count + 1, last_used_at = NOW()
```
Ni `locked_until` ni `locked_by` ne sont settés. La requête WHERE ne filtre pas sur `locked_until IS NULL OR locked_until < now()`.

Pour setter ces champs, le worker devrait utiliser `prisma.$executeRaw()` (car Prisma client ne connaît pas les colonnes) — non implémenté.

### Cleanup ❌ (inexistant)
Recherche exhaustive dans `src/` : zéro occurrence de `lockedUntil`, `lockedBy`, `cleanupExpiredKeywordLocks`, `keyword-lock-cleanup`. Les deux workers cron existants (`booking-crons-worker.ts`, `image-bank-crons-worker.ts`) ne couvrent pas les keyword locks.

## Conséquence en production
Le bug P0-5 original **n'est pas corrigé** au niveau applicatif. Si un worker crashe après sélection d'un keyword (après UPDATE usage_count) mais avant publication d'un article, le keyword reste consommé définitivement sans mécanisme de libération.

## Effort correctif résiduel : ~1.5h
1. Synchroniser `schema.prisma` (ajouter `lockedUntil DateTime?`, `lockedBy String?` sur Keyword)
2. `keyword-selector.ts` : SET `locked_until = NOW() + INTERVAL '15 minutes'`, `locked_by = ${jobId}` dans le UPDATE
3. Ajouter `WHERE locked_until IS NULL OR locked_until < NOW()` dans la requête SKIP LOCKED
4. Ajouter cleanup cron dans `image-bank-crons-worker.ts` ou créer `content-gen-crons-worker.ts`
