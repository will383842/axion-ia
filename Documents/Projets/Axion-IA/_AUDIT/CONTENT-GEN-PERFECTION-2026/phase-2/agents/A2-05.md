### Analyse configurabilité

**JUDGE_THRESHOLDS (llm-judge.ts) — Hardcodé `as const`** :
- Les seuils 8.5 (publish) et 7.0 (improve) sont des constantes TypeScript immutables au runtime.
- Commentaire dans le fichier dit "default DB-managed via ContentGenConfig.editorial_review" mais aucun code ne lit effectivement ContentGenConfig pour ces seuils — c'est une intention non implémentée.
- Le reviewer (`llm-judge.ts:207-208`) utilise directement `JUDGE_THRESHOLDS` sans passer par la DB.
- **Gap critique** : pas de hot-reload possible — modifier les seuils LLM-judge nécessite un redéploiement.

**QualityLoopSettings — Partiellement DB-managed** :
- `getQualityLoop()` lit depuis `ContentGenConfig` (table key/value) avec `readContentGenConfig()`.
- `minScoreThreshold` (défaut 75) et `targetScore` (défaut 85) sont modifiables admin sans redéploiement.
- `updateQualityLoop()` valide les plages (0-100, maxAttempts 0-5, budget 0-5000) — protection seuils aberrants présente.
- MAIS ces seuils (quality-loop) sont distincts des JUDGE_THRESHOLDS (llm-judge) — deux systèmes parallèles sans cohérence garantie.

**DEFAULT_QUALITY_THRESHOLDS (knowledge/quality-thresholds.ts)** :
- 25 seuils par KbType codés en dur, pas de DB-managed.
- Commentaire "paramétrables via `Setting.kb.quality.threshold.<type>` runtime override" mais la fonction `getQualityThreshold()` ne lit que la constante locale — l'override runtime n'est pas implémenté.

**QUALITY_THRESHOLD dans generators** :
- 3 constantes distinctes dans 3 fichiers générateurs (55, 60, 60) — dupliquées, pas centralisées, pas DB-managed.

**Valeurs raisonnables** :
- PUBLISH_MIN 8.5/10 (85%) = strict mais cohérent avec standard éditorial.
- IMPROVE_MIN 7.0/10 (70%) = seuil d'amélioration raisonnable.
- Pas de protection contre seuils aberrants sur JUDGE_THRESHOLDS (pas de validation car `as const`).

### Design DB-managed recommandé (non implémenté)

Le commentaire dans `llm-judge.ts` mentionne "DB-managed via ContentGenConfig.editorial_review" mais cette clé n'est jamais lue dans le code. Le design serait :
```
ContentGenConfig["editorial_review"] = {
  publishMin: 8.5,
  improveMin: 7.0,
  maxImproveIterations: 2
}
```
avec `readContentGenConfig("editorial_review", JUDGE_THRESHOLDS)` dans `runLlmJudge()`.

**Score justifié** : Seuils quality-loop DB-managed corrects (5/10), mais JUDGE_THRESHOLDS hardcodés `as const` malgré la promesse DB-managed (design incomplet, -6), 3 QUALITY_THRESHOLD dupliqués dans generators non centralisés (-3), DEFAULT_QUALITY_THRESHOLDS 25 valeurs hardcodées (-2), protection seuils aberrants partielle (+2 pour quality-loop uniquement) = **8/20**

### P0-3 : JUDGE_THRESHOLDS hardcodés `as const` malgré promesse DB-managed
- Le commentaire dans `llm-judge.ts:18` dit "DB-managed via ContentGenConfig.editorial_review" mais la clé n'est jamais lue.
